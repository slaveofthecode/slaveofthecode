# slaveofthecode portfolio

Living CV site: profile, experience, skills, languages, "What I'm working on now",
personal projects, and an AI chat for recruiters. English only. Talk to the human in
Spanish; write code/docs/commits/PRs in English.

## Layout
- packages/content: Zod schemas + one CV data file (`data/cv.json`). SINGLE SOURCE OF TRUTH.
- apps/web: Astro + Tailwind, static output. UI strings live in `src/lib/strings.ts`.
  Both PDFs are generated at build time from the CV JSON.
- apps/api: Node-compatible TypeScript backend (chat + RAG). No locale or translations.
- docs/: architecture, workflows, decisions, STATUS.md (memory), learnings.md

## Commands (Bun, from repo root)
bun install | bun run dev | bun run lint | bun run typecheck | bun test | bun run build
bun run check:boundaries | bun run format:data | bun run --filter @portfolio/api build:rag

## Rules
1. Never invent CV data. Facts come only from `packages/content/data/cv.json`.
2. Theme tokens only (CSS variables). No hard-coded colors.
3. Git: NEVER run git commit/push/merge or gh pr merge. The human commits and pushes.
   Never work on main directly. Branch from an up-to-date main (docs/workflows/start-feature.md).
4. PRs: only after the human pushed, per docs/workflows/open-pr.md (base main, assignee @me).
5. Done = lint + typecheck + test + build + check:boundaries pass. Report what you could not run.
6. One feature per branch; small diffs; no new dependency without justification.
7. Dependency rule: web and api never import each other; both may import @portfolio/content only.
   No Bun-only APIs in apps/api or packages it uses.
8. Session start: read docs/STATUS.md. Task end: update it.
9. Reusable lessons go to docs/learnings.md as proposals. Do not edit this file yourself.
10. Public repo: `content-source/` stays gitignored (the raw working copy). The public
    `apps/web/public/cv.pdf` and `apps/web/public/cv-ats.pdf` are generated from the JSON
    during `bun run build` (ADR-0007). Contact data in `packages/content/data/cv.json`
    (location, email, phone, links) is intentionally published and must be shown in full.
